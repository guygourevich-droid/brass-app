# Tonebee (טונבי) — formerly Brass App

Music teacher's toolkit for brass and rhythm lessons: kids 9–12, projected in class, and installed on an iPad for offline use. Live at https://tonebee.app — Cloudflare Workers static assets, deployed with `npx wrangler deploy` (`wrangler.jsonc`, `.assetsignore`; `worker.js` only maps `/` to `index.html` because `html_handling` is `none`, so `.html` URLs never redirect). The old GitHub Pages copy (guygourevich-droid.github.io/brass-app) is being retired. Business side (plan, brand, decisions) lives outside this repo in `../ops/`. Brass-specific tools (trumpet first) are planned but not yet designed.

## Constraints
- Plain HTML/CSS/JS only. No build step, frameworks, CDNs or backend (`worker.js` is edge routing only) — every page must work offline.
- Brand name on screen comes from COMMON `brand` ("טונבי" / "Tonebee") via `data-t="brand"`; localStorage keys keep their old `brass-*` names on purpose (renaming would wipe saved settings).
- One tool = one self-contained HTML file at repo root + a tile in `index.html`.
- New or renamed file → add it to `FILES` in `sw.js` and bump `CACHE`, or installed iPads keep serving the old copy.
- Fonts are self-hosted in `fonts/`; never link Google Fonts.
- British note names (crotchet, quaver…). In Hebrew, note names on screen default to fixed do-re-mi (דו רה מי…), with a C D E option; English always uses letters (C D E, B♭) and hides the choice.
- Big, clear type — read from a projector. Clap-Along is clean white; the breathing, buzzing and note tools share a playful sky look.
- Transposition matters: students always see their WRITTEN note (trumpet in B♭ and horn in F in treble clef, trombone in bass clef); sounds play at CONCERT pitch (trumpet −2, horn −7 semitones, trombone 0).
- Discuss and agree what a new tool does with the teacher before building it.
- Classes are 4-6 absolute beginners, ages 9-12, one laptop + projector. Lesson 1 asks "did a sound happen?", not "was it the right note".
- Traffic light, everywhere it appears: red = stop/instrument down, yellow = get ready and breathe, green = play. Manual, teacher-controlled. Never flash it, never faster than one change per 250 ms, and never let colour be the only channel (position, shape, fill-vs-outline, size, word).
- The microphone may only ever add a glow. Silence is a waiting state, never failure; nothing turns red; no individual score reaches the projector; the counter counts attempts and only rises.
- Two languages, Hebrew (default) and English, chosen once on the home screen and never mixed on one screen (the teacher's rule). Every page carries the same "Language" block after `"use strict"`: `LANG` (`brass-lang` in localStorage, `?lang=en|he` overrides), `COMMON` (shared words), the page's own `TEXT = { he, en }`, `T(key, ...args)` (values may be functions or arrays) and `applyText()`, which sets `lang`/`dir` and fills `data-t` / `data-t-html` / `data-t-title` / `data-t-aria`. A tiny `<head>` script sets `dir="ltr"` before first paint for English. Every new on-screen word goes into both `he` and `en`. SVG text sets its direction from `LANG`.
- Pages are written Hebrew-first (`lang="he" dir="rtl"`), near-wordless, and use Rubik in Hebrew. Use logical CSS (`margin-inline-*`, `text-align: start`). Keep music notation `direction: ltr` or the clef mirrors. Keyboard shortcuts read `e.code`, never `e.key` (a Hebrew layout turns F into כ).
- Phones and tablets too (most first-time visitors are on a phone): every page must fit a 360×640 phone upright, an 844×390 phone on its side and a tablet, with no sideways scroll; the projector view stays as it is. Touch screens (`(hover: none) and (pointer: coarse)`) never show keyboard hints (`.keys`). Upright phones (≤600px): compact one-line top bar with the app icon as the way home; wide picture games anchor their scene to the bottom (`fitScene`, `xMidYMax`) and suggest turning the phone (`.turn`, COMMON `turn`); Songs shows 2 bars per line (`setLineBars`). Short screens (`max-height: 500px`) drop extras (tips, info lines) so the controls fit.
- Trumpet, trombone and horn classes have different teachers: on-screen tips stay universal (posture, breath, steady air, rest), no instrument-specific technique.

- iPad microphone (all seven mic pages, same block after `"use strict"`): the analyser is pulled to `destination` through a zero gain (old WebKit fed unpulled analysers zeros), the engine is recreated if the mic's sample rate differs, any tap resumes a suspended/interrupted engine, `getFloatTimeDomainData` is shimmed for Safari < 14.1, and exact-zero input for 3 s shows "אין קול מהמיקרופון". Tapping the mic status opens the check panel (no keyboard on iPad); its first lines: engine state, rate and whether its clock moves (זז/עומד); the mic track state, rate, raw vs voice and ec/agc; the raw level in dB. iPad/iPhone (`IS_IOS`; iPadOS Safari claims to be a Mac, so touch points decide) open the mic in voice mode (`audio: true`: voice processing + automatic gain) — raw mode was measured far too quiet on the teacher's iPad (−58 dB with a horn playing; voice mode worked). Desktop keeps raw. `?voice=1` / `?voice=0` force either. The iOS Simulator gets no Mac microphone input here — it can test WebKit code paths, not real sound.

## Map
- `index.html` — home screen, tool tiles, service worker registration. First visit opens setup: language (עברית / English, words not flags), then instrument (`INSTRUMENTS`: trumpet, trombone, horn ready; saxophone, flute, clarinet, recorder shown as "coming soon"). Saved as `brass-lang` / `brass-inst`, which every page reads; the masthead button reopens setup. The instrument is chosen only here: the games have no instrument switch (the teacher's decision: once chosen, the whole app is for that instrument). Instrument pictures are `icons/inst/<id>.png`, cut (circle + instrument, no words) from a picture sheet the teacher supplied. Tile words come from `TEXT` (`t_*`, `d_*`, `c_*`).
- Pause: every game has ⏸ in the top bar and Esc (Esc/Space/tap resumes). Long-note, breathing and buzzing skip their frame loop while `paused`. Ninja, Songs, Right Note, Horn Ladder and Clap-Along use a "Pause" block after `"use strict"` that freezes the page clock (wraps `performance.now` and `requestAnimationFrame`) and suspends the audio engine (`pauseAudio()`), so timers, counts and scheduled sounds all wait; their pause screen keeps a "■ stop" link where Esc used to stop a round. Not in Note Names (no clock) or the traffic light (Esc = lights off).
- `balloon-breath.html` — "נשימה", breathing: one press (Space / clicker / tap the picture) = one breath, nothing starts by itself. Breathe in 4 → blow out 4/8/12/16 (`LEVELS`), no hold. Two `WORLDS`, same breath: 🫧 bubble (in: wand dips into the soap; out: one bubble grows from the ring at a steady rate, bigger for longer levels; end: it floats up to a `SLOTS` place in the sky) and 🌼 dandelion (in: bud opens into a seed ball; out: the breeze takes the seeds one by one, the last as the breath ends; end: a yellow flower grows in the meadow). N clears the sky/meadow. Microphone optional, asked on the first breath: blowing heard → golden breeze, a little faster, never anything else. The teacher rejected a windmill → electricity → village version: kids don't connect windmills to power; the breath must touch the thing directly. `?test=1` + `testBlow(gain)`, `?world=dandelion`.
- `buzz-along.html` — "זמזום", mouthpiece buzzing with a bee, in the teacher's own order. 1 🐝 any buzz flies the bee across the meadow, buds open as it passes (no pitch). 2 🌸 the app buzzes a note (listen first), a flower grows to that height; the bee's height = the child's pitch; in the band (±80 cents, out at 110) the bee flies over and lands → honey drop to the jar; after a success a big button (פרח הבא / עוד מסלול) or Space moves on (`TARGETS`, semitones above the first buzz). Bee starts at the left edge, flower at the right end. 3 🍯 same, stay landed 4 or 8 s to fill the honeycomb; off the pitch only pauses it. 4 〰️ free: the bee draws its pitch as a trail; route (a 2nd, 3rd or 5th): the starting buzz plays with a 3-2-1, then the bee flies on at a steady speed home to the hive over a tree, a house and a sunflower, one siren each (`routeSemi`); the buzz lifts it, silent it glides back to the starting height (the teacher wanted it to keep going, not pause); dots only over the obstacles, the flat stretches are for breathing; too low over an obstacle → the bee bumps, gets dizzy (stars, soft boing) and the route restarts — the teacher asked for this, an agreed exception to "silence/nothing fails"; free-draw ✏️ is the last option, 〰 2 the default; dots bloom when met, a top map shows the way, the hive ends it. `INSTRUMENTS` = concert first-buzz pitch, chosen by the teacher: trumpet B♭3 (written low C), horn F3 (written low C below the staff), trombone F3; `TARGETS` go a little down as well as up. Model buzz = synthetic (bright pulse wave, formant lifts, breath, scoop, wobble) unless `sounds/buzz/<instrument>.m4a` exists (a steady buzz on the first note; pitch-shifted). Same listening as the long-note game (tone + 12 dB + steady onset; floor frozen while buzzing). `?test=1` + `testBuzz(semitones, gain)` / `testNoise(gain)`.
- `note-names.html` — note reading: `INSTRUMENTS` holds clef, transposition and first notes in teaching order (trumpet/horn written C4→C5, trombone B♭2→B♭3); level n = first n+1 notes. Clefs/notes drawn with the Bravura font (SMuFL code points).
- `ramzor.html` — the traffic light: three lamps (octagon/triangle/circle), teacher-controlled, optional hold bar, works from a presentation clicker. No microphone, no network: this is the fallback if anything else fails.
- `sound-game.html` — "צליל ארוך", the long-note game: one steady note flies a rocket up from the ground into space; the world scrolls past (birds, plane, clouds, satellite, astronaut, Moon, Saturn, comet, UFO…) and the sky darkens with height. `LEVELS` = 4/8/12/16 s (ending at the sun above the clouds, satellite, Moon, Saturn) and ∞ (as far as you can: big seconds count up, and back home it shows the turn's longest note — the teacher asked for this number, an agreed exception to "no individual score"; places reached this turn also stay in a top-corner row). `CHECKS` = places every 4 s (new ones through 60 s via `DEEP`, then again in new `HUES`), `SIGHTS` = things on the way; the sky goes day → night → purple → teal → magenta (`#sky2`…`#sky7`), with a bigger cheer every 20 s. No pitch and no instrument choice: a note starts when a clear tone (80–1000 Hz) is 12 dB over the noise floor and steady for 250 ms (talk, claps and breath do not count), keeps going down to 6 dB with 300 ms gaps forgiven, and the floor never rises while a note sounds. Stopping → parachute home; arriving celebrates once and waits for silence. `?test=1` + `testSound(gain)` / `testNoise(gain)` in the console.
- `right-note.html` — the staff exercise: target note + the note actually played, teacher picks which written notes are in play (per instrument, saved in localStorage), hold to win, then it moves to another chosen note. Hebrew note names only.
- `horn-ladder.html` — "סולם", open notes (no valves; trombone 1st position) as ladder rungs, for all three instruments (`INSTRUMENTS`, shared `brass-inst`). Horn: open F horn partials, written C3…G5 = partials 2–12, 11 skipped, a long ladder. Trumpet (written C4 G4 C5 E5 G5) and trombone (B♭2 F3 B♭3 D4 F4): partials 2–6, a short ladder of far-apart rungs, 2–5 shown by default; rungs with no recording borrow the nearest one, pitch-shifted (`sampleHz` reads the pitch from the sample's name). Two kinds (header): "דו רה מי" = the notes the class knows, step by step, read from and written to the shared picker `right-note-<inst>.chosen` (`SCALE`: notes, defaults and every recording; each rung borrows the nearest recording) — the default for trumpet and trombone, as the teacher asked; "פתוחים" = open notes, the default for horn. Settings saved per instrument (horn keeps `horn-ladder`), banana rungs per kind (`targets` / `scaleTargets`). Rungs placed half by pitch, half evenly. A monkey climbs to the partial being played after it is steady 300 ms; banana mode = target rung, hold to win. Targets are the natural partial pitches (B♭4 ≈ 31 cents flat), not equal temperament. Reference = real horn recordings in `sounds/horn/` (Univ. of Iowa MIS ff, no restrictions; named by CONCERT pitch, `off` = measured cents per recording, corrected at playback). `?test=horn` loops a recording into the detector; `testTone(n, cents)` in the console. Noise floor does not rise while a note is heard (a long tone otherwise goes deaf after ~15 s — the other mic pages still have that behaviour).
- `ninja.html` — Note Ninja, all three instruments: one child per round of 3–10 notes from right-note's shared picker (`right-note-<inst>.chosen`; own round settings in `ninja-<inst>`). Note flies in on the staff, optional real-instrument reference first (the clock pauses while it plays), hold 500 ms within ±50 cents → ninja slices it; time out → note drifts away, round continues. The dots on top show the round: ⭐ sliced, grey ✕ missed (a missed note greys, shakes, bloops softly and drifts); a small 🔥 streak in the top corner above the ninja (not in the stars' row) from two in a row, its chime climbing; every note sliced = "מושלם! ⭐" (the teacher asked for misses, streak and a perfect round: an agreed exception to "no individual score"; still nothing red). End: three celebration levels in words; teacher presses Space for the next child. `SAMPLES` = recordings per instrument in `sounds/<inst>/` (concert names, measured cents off). `?test=1` + `testTone(writtenMidi, cents)`. A hidden Browser pane throttles rAF to ~3 fps; for timing tests, swap `requestAnimationFrame` for a MessageChannel pump.
- `songs.html` — whole songs, one child. `SONGS` = melodies as "step:beats" in 4/4, bars split by `|` (steps index the instrument's right-note note list, so trombone plays in B♭ with a 2-flat key signature, trumpet/horn in written C); titles Hebrew only on screen (`en` kept for an English version — no mixed languages). A song is playable only if all its steps are ticked in the shared picker; the others are listed after it, faded and 🔒, with their missing notes marked ("+ סול"), and open the settings when tapped; with none playable a big "⚙ לבחור צלילים" button shows (it looked like a bug when the list was just empty). One line of four bars at a time; the next line waits below at half size, faded, and slides up into place (the finished line drifts off above). The band (🥁, on by default): chords worked out from the melody per half bar (`harmony`: I/IV/V/vi, fa counts half for V), drums and a bass under the instrument's range. 🎧 Listen: a bar of count-in, melody on the real recordings + the whole band. Follow ("לומדים"): hold 250 ms per note; if the child is already on one of the next two notes (another pitch, not the tail of the note just played), it catches up and the skipped note goes light green — the teacher's complaint was that a missed detection killed the flow; a repeated pitch needs a new attack (short-window envelope dip), or just a re-hold with "מספיק להחזיק". In time ("בקצב"): one-bar count-in, then the band plays drums and bass only (chords hold the melody's notes and could be heard as the child); 🎺 "עם המנגינה" adds the melody to play along with — notes are then marked only with iPad voice mode (its echo cancelling removes the device's own sound), never with a raw laptop mic. Notes judged by when the sound was made (`DETECT_LAG_MS`), a repeat needs its own attack; the floor does not rise while playing in time. Section = bar range. When the Saints was left out: no published melody was found to confirm the middle phrase.
- `clap-along.html` — "קצב", rhythm game. Hebrew counts "1 ו 2 ו" with a dot for semiquaver steps, quiz answers א ב ג; English 1 & e a, A B C. Sections: rhythm model (`LEVELS`, `STARTS`, generator, quiz distractors) → SVG notation → Web Audio (`Sound`) → game state and wiring.
- `fonts/Bravura.woff2` — music symbol font (SIL OFL), needed offline for Note Names.
- `sw.js` — network-first with 3 s timeout, cache fallback.
- `manifest.json`, `icons/` — iPad home-screen install.
